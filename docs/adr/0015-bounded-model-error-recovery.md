# 15. Bounded recovery for end-of-turn model errors

A harness may end an agent turn with a transient stream failure while Herdr still reports an idle Rider. A generic `worker_idle` Notice waits for `idle_after` and loses the actionable cause. On a known harness's end-of-turn event, Posse reads the recent pane output and recognizes only explicit per-kind error signatures. The first supported signatures are Pi stream disconnects and provider content-filter refusals.

The observation starts a durable, launch-scoped episode. Pi errors are recognized from the rendered error result: a standalone `Error:` line or an unprefixed `stream error:` line with a known provider signature followed by Pi's fixed `/bug` help line and only terminal footer content, including one visible working-directory line (`/…` or `~/…`) before the status line. A pane tail may start inside an earlier tool panel, so an unmatched rule immediately before the error closes that truncated panel unless a rule immediately after the help line confirms the candidate is inside a bordered panel. Tool output after an opening rule remains ignored. A matching block inside Pi's bordered tool-result panel, including `$ command` shell output, cannot trigger recovery. A stream-disconnect episode receives at most three `continue` nudges, with 250 ms, 500 ms and 1 s backoff. Attempts are charged before prompt submission. A new idle turn may reuse the same screen fingerprint. The persisted turn state admits a failed turn after Herdr reports working, even if normal reconciliation has already recorded the Rider as idle; duplicate idle hooks before that transition remain deduplicated. Before submitting, Posse rechecks the Task's working state, launch and pane ownership, the active episode, queued messages, and the focused/blocked pane guards. A needs-decision or terminal Signal atomically blocks the active episode. If a charged attempt remains incomplete until its backoff deadline plus a five-second submission lease, Posse marks it interrupted and raises a specific Notice instead of replaying an uncertain prompt. An active episode with no pending attempt retains the delayed `worker_idle` fallback if its end-of-turn hook is missed. A successful later turn resolves the episode. Exhaustion, refusal, safety refusal, interruption, or a queued Lead instruction produces a specific `model_stream_error` or `model_refused` Notice as appropriate. Refusals are never retried. `posse show` exposes the current episode, and `posse show --full` exposes the audit signals.

All prompts pass through the standard snapshot-based focused-pane and blocked-agent checks. There is no timer service; the Herdr end-of-turn hook drives detection and recovery. Unknown harnesses and output that does not match a known signature retain the existing idle behavior.
