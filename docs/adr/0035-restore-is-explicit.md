# 35. Restore is explicit

On 2026-10-26 a Herdr restart made automatic recovery relaunch a Project's Lead as `pi`, although a Claude Lead had been running. The restarted pane had no agent, so recovery fell back to `lead.kind`: Posse never recorded which agent the Lead actually was. The User then ran `posse up --claude` and was refused because the wrongly restored `pi` Lead was now running. The User also closes Herdr deliberately most of the time, so relaunching agents on the next event was unwanted in the first place (issue #540).

Posse no longer starts a Lead or Worker on its own after a Herdr restart, a closed Lead workspace group or a closed Lead pane. The Herdr startup hook (`posse _herdr_started`), plugin events, the Watch and other commands still detect the new generation or the group close, but only record it: they keep the stale panes and Task states, keep the generation pending, and raise one `restore_needed` Notice per episode naming the stopped Lead and Workers. `defaults.auto_recover` is removed. A config that still sets it fails to load with an error that names the replacement, rather than being ignored, because silently changing what a restart does is the surprise this decision removes.

The User restores with `posse up --all`. It visits every Project that is not down, relaunches the Workers the restart stopped through the bounded relaunch path, starts the Lead when none is running, and ensures the Watch. A Project whose Lead is running keeps it, so the command is safe to repeat. `posse up` in one Project's folder still restores that Project alone. `posse down` keeps a Project out of `--all`.

`--all` extends `posse up` instead of keeping `posse recover --all`. Bringing a Project's Lead up is already `posse up`'s job, and the User should learn one verb for "make my Projects run". `recover` keeps only `--rebuild`, which repairs the database from snapshots and starts nothing; `recover --all` fails with `command_removed`. Folding restore into `up` also lets `--all` share `up`'s Lead start claim, kind selection and session handling.

Posse records the Lead's agent kind and session in `project_runtime` when it launches a Lead and whenever a reconcile of the current Herdr generation sees an agent in the Lead pane. Herdr's detection is the source, not the kind Posse last started, because the User may have started another agent in the Lead pane by hand. A restore and `posse up` without a kind flag use the recorded kind while it is still configured and resume its session through the kind's `resume_args`; `lead.kind` is the fallback only when nothing usable is recorded. A kind flag for another kind, `--replace`, or `posse down` starts a new conversation. The record lives in runtime state rather than the Project snapshot: after `recover --rebuild` it is empty and the fallback applies.

This amends [ADR 0004](0004-start-lead-in-calling-pane.md): the Lead restart that has no caller pane is now `posse up --all`, not `posse recover`.
