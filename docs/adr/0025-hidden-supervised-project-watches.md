# Hidden supervised Project watches

ADR 0001's CLI-owned mechanics and no-daemon boundary do not require every process to be short-lived: PR, CI and checkout observation must continue while a Lead is idle, so each active Project owns one detached watch supervised by CLI commands, Herdr events, hooks and extensions, with its identity and heartbeat persisted in SQLite. This amends ADR 0001 only by introducing that narrowly scoped supervised child; Herdr remains the runtime and source of truth, and Posse adds no general daemon. It also narrows ADR 0005's rejection of detached Watches: the Project watch may deliver Notices through the configured Lead delivery path when no extension or live Lead Watch owns delivery. It never acknowledges Notices; harness queues, hooks and extensions retain their existing ownership rules. Passive Watch intent recovery is deliberately limited to interrupted `merge --open-pr` recovery after the Lead is running. Crashed `teardown`, `merge --execute`, workspace merge, `start` and `relaunch` intents remain for the next normal Project command because a poll tick must not take ownership of command-boundary side effects. Supervision adopts or stops managed poll-only processes with a complete private Project id, token and start time. A bounded foreground `posse watch --poll-only --timeout <ms>` remains a User wait. An unbound indefinite poll-only process running inside the Project is treated as leaked compatibility state and reaped after its executable identity is verified; it is never adopted as the managed Watch.
