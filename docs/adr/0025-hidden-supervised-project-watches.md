# Hidden supervised Project watches

ADR 0001's CLI-owned mechanics and no-daemon boundary allow a narrowly scoped Project watch because PR, CI and checkout observation must continue while a Lead is idle. On Linux with a systemd user manager, each active Project runs its watch in a transient user service with `Restart=always`, `MemoryMax` and `TasksMax`. The user manager owns the service outside the launching terminal and Herdr or Ghostty scopes. On systems without a systemd user manager, Posse retains its detached-process supervisor. SQLite stores the watch identity and heartbeat in both modes, and the existing per-Project lock and token prevent duplicate watches during transitions between modes. Herdr remains the runtime and source of truth; Posse adds no general daemon.

The Project watch may deliver Notices through the configured Lead delivery path when no extension or live Lead Watch owns delivery. It never acknowledges Notices. Passive Watch intent recovery remains limited to interrupted `merge --open-pr` recovery after the Lead is running. Crashed `teardown`, `merge --execute`, workspace merge, `start` and `relaunch` intents remain for the next normal Project command. Supervision adopts or stops managed poll-only processes with a complete private Project id, token and start time. A bounded foreground `posse watch --poll-only --timeout <ms>` remains a User wait. An unbound indefinite poll-only process inside the Project is treated as leaked compatibility state and reaped after its executable identity is verified; it is never adopted as the managed Watch. `posse update` asks the running watch to re-exec onto the installed binary, and `posse doctor` reports its state and systemd unit.
