# Hidden supervised Project pollers

ADR 0001's CLI-owned mechanics and no-daemon boundary do not require every process to be short-lived: PR, CI and checkout observation must continue while a Lead is idle, so each active Project owns one detached poller supervised by CLI commands, Herdr events, hooks and extensions, with its identity and heartbeat persisted in SQLite. This amends ADR 0001 only by introducing that narrowly scoped supervised child; Herdr remains the runtime and source of truth, and Posse adds no general daemon. It also narrows ADR 0005's rejection of detached Lookouts: the Project poller may deliver Notices through the configured Lead delivery path when no extension or live Lead Lookout owns delivery. It never acknowledges Notices; harness queues, hooks and extensions retain their existing ownership rules.
