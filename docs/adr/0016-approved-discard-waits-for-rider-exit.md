# Approved discard stops the verified Rider

Extend `posse unsaddle <task> --discard --user-approved "<User's words>"` rather than add a separate stop command: the Lead can cancel working or needs-decision Tasks with the same explicit approval and discard safeguards. Retain the current launch's process-start identities and Linux pidfds before any signal. Interrupt with SIGINT, then terminate with SIGTERM and, if needed, SIGKILL; signal only retained instances and proved descendants, never a newly observed process. Keep shell identities for verification, not signaling. Save the User quote and bindings in the intent before signals so crash recovery cannot retarget a replacement. Other platforms or missing pidfd capability refuse before stopping.

Herdr 0.9.1 has no conditional pane close. Approved discard rechecks the server generation, pane topology, launch name, retained shell identity and shell-only foreground immediately before `pane.close`; a replacement or unverifiable identity refuses and keeps the Mount held. Clear stale lifecycle authority only with its source and sequence after rechecking the foreground. Close individual verified Task panes, not whole tabs or workspace groups. Normal Teardown still relies on retained process exit and refuses if a pane remains. The final observation and pane close are separate calls, so an unobserved replacement in that gap remains a Herdr limitation.

Validate every recorded unlanded PR or Member MR before stopping. A preflight merged request refuses before approval; close open requests and reread them as `CLOSED` before Rider shutdown or pane closure. Failed or unverifiable closure keeps the Mount held and panes open. A landed Task's merged PR is not a discard target when an unrecoverable-Leftover Decision disposes of separate unsaved work. After Rider shutdown, record and capture the final approved branch tips, including commits finished during interruption. Verify no residual Mount or scratch processes remain, then remove scratch, release the Mount and delete the exact approved branches. Residual processes never gain signaling authority from a CWD scan. Process-presence scans and Git reset are also separate operations; eliminating that race requires host-level path fencing.
