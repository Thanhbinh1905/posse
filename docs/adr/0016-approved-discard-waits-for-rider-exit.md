# Approved discard waits for Rider exit

A User-approved discard of unlanded work is allowed only after Herdr verifies that the Task's Rider has exited. A direct discard refuses before recording approval; an already-answered Decision may remain answered, but applying it refuses before recording discard approval or changing custody while the Rider is live or unverifiable. Discard never signals a Rider or residual Mount/scratch process and keeps the Mount held until those processes are gone. Herdr 0.9.1 has no conditional pane-close operation, so the Task pane must disappear naturally or be closed manually after the Rider exits; discard refuses while it remains. Live-Rider stopping and `posse stop` remain deferred until A01 #133 and A02 #134 provide safe exact-instance lifecycle handling.

Before pane verification or Mount release, discard validates every recorded PR or Member MR for an unlanded Task against its forge. A preflight merged request refuses discard before approval is recorded. An already closed request is accepted; an open request must be closed and freshly read as `CLOSED`. If the close fails, the forge cannot be re-read, or the request is still open or has merged, discard keeps the Mount held and leaves the panes open. Verified closure is retained in the PR observation history. A landed Task's merged PR is not a discard target when an unrecoverable-Leftover Decision disposes of separate unsaved work. Process-presence checks are snapshots: a process can attach to the Mount after the final scan but before Git resets it; Posse has no host-level fencing operation to eliminate that residual race.
